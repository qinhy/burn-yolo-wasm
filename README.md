# Burn YOLO WASM · web-first detector

A single YOLO11n object-detection pipeline deployed to **Vue 3 + Vite** (web; PWA-capable) and **Tauri 2** (optional wrapper). Model inference is **Burn in Rust compiled to WebAssembly**. No Python, ONNX Runtime, or server is needed at inference time.

```
Ultralytics yolo11n.pt  --ONNX export-->  model/yolo11n.onnx
    --burn-onnx-->  crates/inference/src/generated/yolo11n.rs
                  crates/inference/src/generated/yolo11n.bpk
    --ZIP deflate--> crates/inference/src/model.zip
    --include_bytes + wasm-pack--> src/wasm/pkg/*.wasm + *.js
    --Vite--> dist/ (web)  --> packaged as-is by Tauri 2
```

> **Status:** Full source distribution / integration starter. The model and weights are **not** included. The exact YOLO11n → Burn 0.22.1 conversion and WASM builds have **not been compiled or run** in the environment where this repository was created (Rust toolchain, network and model artifacts were unavailable). See [Verification and limitations](#verification-and-limitations). This is not a claim of production-ready, verified YOLO performance.

## Prerequisites

- Python 3.10+ and CPU/GPU PyTorch, `ultralytics`, `onnx`, `onnxscript` and optional `onnxruntime` (install from `requirements-export.txt`)
- Rust stable, `wasm32-unknown-unknown` target and `wasm-pack`
- Node.js 20+ and npm
- Optional Tauri 2 prerequisites for your operating system, and `@tauri-apps/cli` via npm devDependencies

## Get started

```bash
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
python -m pip install -r requirements-export.txt

rustup target add wasm32-unknown-unknown
cargo install wasm-pack
cargo install burn-onnx --version 0.22.0

# Download yolo11n.pt (on first Ultralytics use), export a static 320x320 ONNX,
# generate Rust + burnpack using Burn, ZIP the weights, emit model metadata.
python scripts/prepare_model.py

npm install
npm run dev
```

Then visit `http://localhost:5173`, upload or drag in an image, or start the camera. The first WASM initialization decompresses weights and loads them once. Choose **Auto** to attempt WebGPU and fall back to Burn Flex CPU if GPU initialization fails. For lowest latency, explicitly select GPU on a WebGPU-capable Chromium browser. `npm run dev` builds the WASM automatically using `predev`.

### Deploy

```bash
npm run build                  # web: dist/
npm run preview                # local production test
npm run desktop:dev            # Tauri development shell
npm run desktop:build          # Tauri bundle (platform prerequisites required)
```

The web app and Tauri app use the **same compiled assets**, including the WASM model. Tauri has no separate YOLO inference backend.

## Model configuration

- Default: `yolo11n.pt`, **detection** (not segmentation), static **[1, 3, 320, 320]** FP32 input.
- Export: `nms=False`, `dynamic=False`, `opset=17`, `simplify=False`, `half=False`. Raw YOLO11 detection predictions are expected as `[1, 4 + classes, anchors]` (COCO80: `[1,84,2100]` at 320px).
- Input is BGR-independent **RGB**, float32 0..1, NCHW; image is letterboxed with fill `(114,114,114)`.
- Output is decoded as center-XYWH + class probabilities, then **class-aware greedy NMS** in Rust. Overlay converts coordinates back to the original image.
- Rust model and ZIP weights are included in WASM via `include!` and `include_bytes!`. Neither requires filesystem at runtime.
- `scripts/prepare_model.py --weights path/to/custom.pt` can use custom detection weights. The script rewrites `src/model-meta.json` with the model class names to match its output.

## Verification and limitations

- **Not benchmarked:** wasm compile, YOLO11n Burn import, end-to-end model outputs, and GPU performance require running the commands on a machine with Rust/model downloads. Importer operators are evolving; an unsupported operator or generated-code mismatch may require a different model/opset or Burn version. The build fails visibly rather than silently falling back to an unrelated runtime.
- **GPU caveat:** Burn's WGPU/WebGPU initialization uses browser GPU APIs; GPU availability in Web Workers differs across browsers and embedded WebViews. Auto falls back to Flex CPU if initialization fails; runtime GPU errors are surfaced rather than silently ignored.
- **CPU performance:** Flex WASM convolution on 320px YOLO may be slow. Adjust input size (must rerun all build steps) or use WebGPU; browser memory can be substantial.
- **ZIP trade-off:** packing `.bpk` in deflated ZIP is not always smaller over network than Brotli-compressed raw WASM. It increases peak memory while unpacking.
- **Model/weights license:** Ultralytics YOLO11 code and pretrained models may be subject to AGPL-3.0 or an enterprise license; independently check your intended distribution terms. This repository's original example code is MIT-licensed; it does not relicense YOLO weights.
- **Browser security:** camera access requires a secure context (HTTPS or localhost). Offline service worker support is deliberately not forced by default; consider deployment caching separately.
- **Not pixel-identical:** WebView browser versions vary by OS. Shared source and inference help preserve behavior but cannot guarantee identical GPU availability, performance, or rendering across platforms.
